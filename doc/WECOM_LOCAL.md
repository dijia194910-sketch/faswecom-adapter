# 企业微信本地读取版

0.4.1：增加当前账号 SQLite / JSONL 导出、会话与日期筛选和增量游标；修复迁移磁盘后旧目录优先级并细化解锁诊断。详见 [数据库导出](WECOM_EXPORT.md)。

本分支在 faswecom 上增加独立的 Windows 企业微信入口，平台标识为 `wecom`。
读取当前 Windows 用户本机企业微信的聊天数据库，不需要开通企业会话存档。
现有 QQ/个人微信版仍使用原入口；企微版使用独立网页端口 7863、MCP 端口 18778。

## 启动

需要 Windows x64、Python 3.12 或 3.13，以及已登录的 Windows 企业微信。

```powershell
.\start-wecom.ps1
```

第一次启动自动创建 `.venv` 并安装 `requirements-wecom.txt`。也可以手动运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-wecom.txt
.\.venv\Scripts\python.exe -X utf8 app_wecom.py
```

打开 <http://127.0.0.1:7863>，选择本机账号，点击「解锁读取器」，然后选择会话和日期并导入。
再次点击导入会刷新本地数据库快照并去重。读取完成的界面显示新增、已有和未解析消息数。
停止通过启动脚本启动的服务：`.\stop-wecom.ps1`。它只停止本源码目录对应的 Python 进程。

分析、检索和回复入口：<http://127.0.0.1:7863/console>，详见 [企微操作台](WECOM_CONSOLE.md)。
操作台默认不调用模型；可先使用本地检索，也可手动配置模型并按次启用分析。

## 已实现与实际验证

- Windows 企业微信 **5.0.0.8002、x86 客户端**，运行于 64 位 Windows。
- 自动发现“文档/WXWork/账号/Data”目录，包括 Windows 重定向的文档目录。
- 基于当前可执行文件的 MSVC RTTI 定位数据库管理器；只读访问进程，逐个验证候选，不使用固定地址。
- 企微 wxSQLite3 AES-128 密码派生、分页解密，以及完整事务的 WAL 校验与重放。
- `message.db`、`session.db`、`user.db` 快照；快照通过 SQLite `quick_check` 后才能使用。
- 普通文本、分段文本、富文本显示名、会话名、群内昵称、发送者、发送时间和本人标记。
- 群聊和单聊、按会话/日期导入、重复导入去重、本地浏览与关键词搜索。
- 复用 faswecom MCP 的平台/会话/日期授权、撤销、检索和原文来源引用。
- 旧消息表迁移保留消息 ID、外键和索引；平台不会冒充个人微信。

这是当次本机兼容性记录，不代表其他版本、账号或电脑已通过验证。
随后重复读取：原有 7,329 条全部去重，新增 1 条（累计 7,330 条），验证了手动刷新。

## 自动同步

后台每 1 秒检查三个数据库及其 WAL 的文件变化，有变化时生成只读快照并导入未入库消息；每 60 秒进行一次兜底核对。按会话和源消息 ID 去重，不以最大时间戳或最大消息 ID 跳过数据，因此晚到消息、补下载历史和新会话都能同步。为保证快照一致性，每次变化仍读取完整快照，并非按页增量解密；大库耗时可能更长。

同步与首次初始化、解锁和手动导入共用互斥锁。失败不会确认该轮变化，会在 2–30 秒退避后重试；仅使用已绑定账号和已保存的读取密钥，不自动切换账号。页面显示最近同步时间及错误，前台每 1.5 秒刷新状态，浏览旧记录时提示有新消息。同步后的记录可由既有 MCP 检索/增量接口读取，不自动调用模型或发送消息。

2026-10-09 本机首次自动同步新增 51 条，累计 7,381 条、107 个会话，单轮耗时 0.453 秒。这是本机单轮同步耗时，不是消息从发送端到本机的端到端延迟保证；消息须先由企微同步至本机。服务关闭后停止监听，重新启动会补抓遗漏。

## 当前限制

- **图片、语音、视频、文件、部分系统/富文本消息尚未解析**，会保留明确占位。不会把媒体访问参数当正文。
- 富文本类型 5/10 的显示名以 `〔名称〕` 保留，暂不宣称已还原原生 @ 目标或所有格式。
- 仅查询当前机器已缓存的历史，不能恢复未同步到本机、已删除或服务端才有的记录。
- 服务运行时自动同步已绑定账号的全部本机会话（含新会话）；可在操作台或数据页暂停/恢复，设置重启后保留。手动导入的会话/日期筛选不限制自动同步；MCP 原有授权范围仍然生效。
- 自动解锁目前支持带对应 RTTI 的 Windows x86 企微；其他架构和后续版本失败时会明确报错。
- 一个 faswecom 数据目录绑定一个企微来源账号。切换账号使用独立源码/数据目录。
- 数据目录在“文档”之外时，可在“账号未识别？指定企业微信数据目录”中检测 WXWork 根目录、账号目录或 Data 目录。这里填写数据目录，不是企微程序安装目录。

## 接入 Codex

需要程序化调用的发送接口时，另见 [企业微信本地适配器](WECOM_ADAPTER.md)。首版使用界面发送；无窗口后台发送尚未实现。

页面下方选择授权范围，点击「开启 MCP 并创建只读连接」，复制生成的配置。
独立连接名为 `tulpa_wecom`，不覆盖已有的 `tulpa` 连接。配置中的凭据仅当次显示。
权限由用户在页面创建/撤销；MCP 工具不能自行解锁读取器或扩大权限。

## 数据与实现

- 原始企微数据库只读打开，不修改、不 checkpoint。快照使用独立临时目录，用后关闭连接并删除。
- 解锁只读取 `WXWork.exe` 的数据库管理器对象，限时、限量，不注入，不提权，不保存进程内存转储。
- 验证后的数据库密钥由 Windows DPAPI 按当前系统用户加密，存放于 `data/wecom-keys/*.dpapi`。
- 已导入聊天和来源归档存放在 `data/`，属于本地明文资料；不会包含在源码包中。
- 脱敏验证输出仅包含数量、格式与错误类型。源码包不得包括 `data/`、`.tmp/`、`reports/`、`.env` 或凭据。
- 底层算法依据 [wxSQLite3 / SQLite3 Multiple Ciphers](https://github.com/utelle/SQLite3MultipleCiphers/blob/main/src/cipher_wxaes128.c)；企微 macOS 社区资料只用于格式交叉核对，未复制其读取脚本到本分支。

## 0.3.8 修复

- 账号发现按实际目录去重；同账号的不同数据库在列表中显示完整目录，未选择时优先使用唯一的运行中目录。成功解锁或导入后记住所选目录，首次设置、同步和原生发送使用同一选择。已选目录离线不会擅自切换到旧副本。
- 数据页“返回操作台”与操作台“数据与同步”采用同窗口跳转。桌面宿主接收固定导航命令，浏览器和旧宿主保留 URL 回退。
- 保留 0.3.7 的微信联系人名称修复及连续发送检测缓存。

安装器会对已有程序文件进行 SHA-256 校验，复用内容相同的文件，仅解压和替换变化部分。新文件在解压时同步计算校验值，应用更新与回滚使用同卷移动，减少运行环境的重复复制；不跳过完整性校验，不修改系统安全设置。首次安装仍需展开内置 Python、OCR 和 WebView2。

## 0.3.9 双版本与代码保护

同时提供功能相同的 `protected` 加固版与 `unprotected` 普通版。普通版保留原始 Python 和 JavaScript，便于调试维护；加固版采用下面的代码保护。两者可在同一安装目录相互覆盖，安装器会移除旧版受管理的原生模块或被替代源码，避免导入时混用；聊天、账号与模型配置保留。

核心业务模块、服务和发送任务入口编译为 Windows x64 / CPython 3.12 原生扩展；发行包不包含其 Python 源码、字节码、C 源码或调试符号。前端及原生发送脚本压缩并混淆局部变量，不分发 source map。覆盖升级会移除已由原生模块替代的旧版程序源码及对应 `__pycache__` 缓存，保留用户聊天、账号与模型配置。

本地保护仅提高逆向成本，不承诺阻止有经验的分析者或 AI 辅助分析；这不是授权锁或账号限制。第三方库、配置、提示词与非核心维护脚本保持可读。开发源码保留，便于维护。

默认构建加固版：`python desktop/build_wecom.py`；普通版：`python desktop/build_wecom.py --unprotected`。加固版构建另需 `Cython==3.3.0`、MSVC x64 构建工具与 Node.js；在 `.cache/wecom-protection/js` 安装固定版本 `terser@5.51.2`。原生编译缓存不随安装包分发，安装器和打包模块回归检查失败会阻止发布。

## 0.4.0 多账号工作台

桌面安装版可在操作台左侧或数据页顶部选择企微账号并点击“切换账号”。首次选择新账号会创建独立工作台并导入该账号的资料；原账号仍保存在原来的 `data` 和 `.env`，无需搬迁。新增账号位于 `data/wecom-accounts/<账号摘要>/`，聊天、Agent 对话、模型密钥、发送授权、回执和 MCP 连接分别保存，不继承其他账号的密钥或发送权限。

切换时停止旧账号的同步和 MCP 服务，再启用所选账号的服务；下次启动恢复上次选择。读取、分析或发送尚在运行时，需等待完成再切换。每个账号页面有独立地址，旧页面和旧适配器凭据不能操作新账号。当前版本在一个桌面实例中同步当前选中的账号。

修复首次解锁失败却提前绑定账号的问题。兼容旧版留下的空账号绑定：发现多个账号且尚未导入成功时先让用户选择，不再自动反复尝试错误账号。已有消息不会自动改绑。多进程解锁会给每个候选进程保留检测时间，避免后面的账号进程被前三个进程耗尽预算。
