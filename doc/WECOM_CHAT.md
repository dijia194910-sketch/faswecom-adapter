# 独立聊天页面

操作台左侧「聊天 · 消息与文件」打开独立页面。左侧搜索联系人或群聊；选择会话后按时间顺序显示本机已导入的记录，支持加载更早消息和搜索当前会话正文。会话列表分页加载，跟随已配置的同步服务刷新。

在底部直接输入文字，Enter 发送、Shift+Enter 换行。中文输入法选词回车不发送，按住 Enter 不会连续提交。操作台助手输入框也采用相同快捷键。搜索框、日期和配置字段保持各自的输入行为。

文字默认通过原生接口发送，支持企业微信 5.0.11.6029 x86 的已有单聊；群聊默认前台桌面方式。可手动选择后台窗口；该方式仍只支持单行文字。窗口方式在无法完整核对草稿或回执时会停止。

文件通过「＋ 文件」、拖入文件或粘贴文件选择，每次一个，1 字节至 50 MB。文字和文件分别发送。文件会暂存于当前账号的 `wecom-chat-files`，校验大小和 SHA-256；点击发送后切换到前台企微，验证当前登录账号、唯一会话标题、完整文件名及确认按钮，再提交。文件通道也需要受支持的 5.0.11.6029 x86 客户端来核对当前登录账号。截断文件名、重名联系人、残留草稿或不识别的确认框会中止。回执只能确认出现文件气泡，文件传输完成状态需查看企微。新文件路径经过合成测试，尚需真实客户端验收。

发送前创建精确绑定接收人、正文／文件、账号与权限代次的许可；同一编号不会重复提交。发送中的页面刷新会重新查询回执，不自动重发。未知结果必须核对企微后继续。原生服务器回执会和已导入原文合并；窗口发送的气泡回执单独保留为本页发送记录。

0.4.2 新增增量会话索引。旧库首次启动会建立一次索引，后续新增消息、改名与删除会更新统计；数据页统计和会话列表不再反复扫描消息正文。
# 0.4.5：发送准备与同步并发

发送辅助进程只读打开已初始化的聊天库，不再重复执行建表、建索引或其他迁移。后台导入占用写事务时，发送校验仍可读取已提交的数据。每次发送保留权限、账号、接收人和原生版本核验；回执未知时仍不会自动重发。回执中的耗时记录增加了授权、资料定位和辅助进程等待阶段，便于区分慢在发送准备还是等待企微回执。

保留 2026-10-20 的令牌保护、发送总开关、界面与查询改动。修正数据库连接跨数据目录复用，以及辅助进程启动清理其他进程正在读取的临时快照的问题。

# 0.4.3：发送准备与本机附件

发送组件随当前账号工作区在后台预加载；预加载只初始化本地组件和版本元数据，不调用发送接口。已有原生连接可以复用，但每次发送仍使用新的单次请求脚本，重新核对账号、接收人和发送许可。

联系人、会话和消息回执改为只读按页解密查询，不再为每次小查询生成整个明文数据库副本。WAL 仅采用校验通过的已提交事务；并发写入时丢弃本次读取结果并重试读取。发送本身不会自动重试。回执文件记录各阶段耗时，以便区分准备、提交和回执等待。

聊天页面可显示本机已缓存的图片，点击查看大图；本机 MP4 视频可播放，普通附件可保存。旧版已经导入的占位消息也会按原消息编号解析，无需重新导入。支持当前已验证的图片类型 14/101、文件类型 15/102、语音类型 16、视频类型 103。企微 SILK 语音可以保存原始文件，暂不支持网页播放。

附件通过当前账号 CacheMapping 数据库的精确映射查找，仅允许当前账号 Cache 目录中的文件；旧磁盘映射只可重定位到该账号现有缓存。不会把 CDN 地址、密钥或本机路径返回浏览器，也不会请求远端附件。未下载、缓存已清理、格式不支持时显示明确提示；先在企微打开附件，再刷新聊天。


## 0.4.6 回复与头像

对方消息下的「帮我回复」使用当前模型和该消息之前最多 16 条会话记录生成草稿，只生成文字，不调用发送接口。输入框为空时自动填入，可编辑后发送；已有草稿时单独显示建议，避免覆盖。

聊天页上方的「当前会话自动回复」默认关闭，各会话独立。先在助手设置中配置模型并开启发送，再打开该开关。开启后只处理此后新同步的对方消息，合并一次同步中连续收到的消息，直接发送并在正文末尾统一加「（AI回复）」，无需逐条二次确认。本人消息、旧消息、非文本占位消息和带同样 AI 标注的消息不会触发。原生文字支持已有单聊；群聊可选择前台桌面，会切换企微窗口。开关启用时固定发送方式，修改方式需关闭后重新开启。

关闭开关会撤销正在生成或核对的自动回复；关闭前已经提交的消息无法撤回。生成失败、发送核对失败或结果不明确时，此会话会自动暂停并显示原因，不会自动重发。重启应用或切换账号后开关关闭，需要重新开启，不补发离线期间消息。应用运行且自动同步导入新消息时才能触发。

头像优先读取当前账号的 Avator 缓存映射；缺失时仅允许通过 HTTPS 从已验证的企微头像域名 wework.qpic.cn、wwcdn.weixin.qq.com 加载，禁止跳转。只向页面返回经过解码、缩放的 PNG 缩略图，头像 URL 不返回浏览器；无法读取时保留昵称首字。群聊列表保留群标记，群内消息可显示发送者头像。

发送核对只读取会话存在性与 last_message_id，避免 SQLite 将无关二进制预览当作 UTF-8 文本解码；不通过丢弃坏字节修改消息原文。

## 0.4.7 聊天切换性能

头像只加载可见区域及其附近的条目，最多两个并发请求，按当前账号与联系人复用缩略图。即使头像服务器响应缓慢，也给消息、接收人核对及同步接口保留浏览器连接。切换会话只更新列表的选中状态，列表刷新复用未变的条目，附件返回后只替换附件气泡，避免重复创建所有头像。

切换时立即移除旧会话的消息，最近 12 个聊天的首屏可先显示短期缓存，同时请求最新记录。取消上一会话未完成的读取，旧响应不会覆盖当前聊天；接收人核对完成即恢复输入，不等待附件或消息请求一同完成。所有发送仍在提交时重新核对接收人和发送权限。

消息头像按消息主键核对归属，兼容旧头像地址时将检索限定在当前会话；同一头像的并发缓存缺失合并为一次读取。附件解析结果复用十秒，进入预览或保存时不重复解析相同元数据；文件大小、修改时间或缓存映射改变则重新核对。缺少缓存或加载失败仍保留昵称和文字，可正常切换。


### 0.4.8 本地头像与启动

头像缩略图保存在当前账号数据目录 `wecom-avatars/`，以账号和用户 ID 的摘要命名；切换页面或退出重开都可复用，无需重新请求头像服务器。首次成功读取后保存，七天后先显示缓存再后台刷新，刷新失败保留原图。消息/账号范围仍需验证；后台刷新最多两个并发。网页仍向本机服务取图，服务命中磁盘缓存时不扫描企微目录、不访问 CDN。

已有数据的账号启动不等待源目录扫描；列出账号只读访问已有数据库。桌面同时准备后台服务与 WebView2，网页 DOM 就绪前显示启动提示，避免空白页。`.tmp/desktop-startup.log` 记录浏览器、服务及网页就绪时间，`.tmp/desktop-service.log` 记录服务准备与监听时间，日志不包含聊天内容。

`wecom-sync-checkpoint.json` 保存成功读取前的源文件指纹及读取后的本地变更水位。重启时两者均匹配才跳过初次快照；源文件、WAL 或本地数据变化均会重新读取。仍保留五分钟周期核对，不把快照期间的新写入标记为已读。
