# 0.3.4 模型保存与大数据性能

模型保存显示进度并防止重复提交，失败提示留在弹窗内。保存成功直接采用接口返回的模型目录，不等待额外状态刷新；设置弹窗可在请求期间关闭、重新打开，后台刷新不覆盖正在填写的内容。

自动同步仍每秒检查文件变化，合并至少三秒内的消息变化；耗时较长时自动延长同步间隔，最多三十秒。账号目录发现复用三十秒，文件未变化时完整对账间隔延长到五分钟。前台状态每三秒刷新，后台每十五秒。

数据库快照分块复制、逐页解密，WAL 逐帧验证，降低大文件的内存峰值。增量导入通过索引排除已导入记录，仍导入时间或 ID 较旧的迟到消息。统计和会话列表按 SQLite data_version 失效缓存，数据库插入或删除后重新计算。回答原文按需展开、每次五十条，减少页面节点。

合成基准见 reports/wecom-034-performance.json：十万条记录的重复统计与 32.5 MB 数据库快照。结果为本机测量，不代表低配机器上的绝对耗时；分块快照增加少量磁盘复制，以减少内存压力。

# 企业微信操作台

启动 `start-wecom.ps1` 后访问 <http://127.0.0.1:7863/console>，或从读取首页点击「打开 faswecom 操作台」。
采用 faswecom 的侧栏对话与提问布局，复用原版 `Sessions`、范围检索、`run_agent`、引用验证及回复起草逻辑。数据范围固定为企业微信。

## 查询与分析

- 左侧新建或恢复历史对话；右侧选择会话、起止日期、补充关键词和分析强度。
- 「我错过了什么」「我答应过什么」「总结最近一周」只填入问题，不自动执行。
- 「本地检索」仅查询本地已导入记录，展示原文及上下文入口，不生成模型总结。
- 右侧「当前模型」可切换已配置的模型；「模型设置」可更新对应接口组的密钥。保存和切换不会请求模型。
- 勾选本次允许调用模型，再点击「开始分析」才会发起请求。运行期间可停止。
- 模型只取得所选企微范围内按需检索的资料；没有发送或授权工具。模型答案继续经过原版引用验证。
- 本次实现验证未调用真实模型。模型驱动、只读范围和回复草稿的连接使用模拟运行器测试。

## 多模型配置

本机目录已导入 `qwen3.7-plus`、`qwen3.7-max`、`qwen3.6-plus`、`deepseek-v4-flash`、`deepseek-v4-pro` 和 `deepseek-reasoner`，默认选择 `deepseek-v4-flash`。目录与密钥不随源码包分发，新安装不会自带这些私有配置。未确认的向量模型未作为聊天模型导入。

配置存放于私有的 `data/wecom-models.json`，密钥使用当前 Windows 用户的 DPAPI 加密保护。浏览器仅收到是否已配置的状态，不会收到密钥；密钥输入框保持空白，留空不修改。同一接口组的三个模型共用对应的密钥，更新一次会应用于该组。已有目录优先于 `.env`；没有目录时保留原版单模型设置。

导入的输出上限为 64000，输入上限为 131072；实际每次输出仍受所选分析强度预算限制。输入上限、超时和重试次数保留为目录元数据，运行时仍采用现有 faswecom 的上下文与请求控制，未完整移植 DeerFlow 参数语义。千问请求携带 `enable_thinking`，强制工具选择时关闭思考以适配工具调用。DeepSeek 保留原有思考参数及工具轮次处理。

“已配置”仅表示本机能解密对应密钥，不代表已验证服务端模型权限、配额或可用性。本轮配置与界面验证未请求真实模型。

## 回复与发送

可直接在对话输入「我想对桃子发送一条信息」或「给桃子发消息：明天下午三点开会」。本机会按已导入的账号昵称查找候选、展示来源会话和账号标识，请用户确认具体接收人。随后填写正文，并在对话里最后确认接收人、正文及发送方式。查找与发送流程不调用模型；目前支持“给/对/向某人发消息”这类明确命令，未声称理解所有自由表达。

点击「确认发送」或回复「确认发送」才会签发本次消息的发送许可；许可固定接收人和正文，保留幂等编号。刷新页面可恢复流程和回执，历史确认按钮不会重复执行。发送进度会显示窗口检查、接收人定位、草稿核对和回执核对；错误会显示具体阶段。已存在且完全一致的草稿可复用，不会重复追加文字；不同草稿保留并拒绝发送。

MCP 在「数据与同步 / MCP」创建连接时，可单独勾选「允许直接发送」。已授权连接提供 `search_wecom_recipients`、`send_wecom_message` 和 `get_wecom_operation`，发送调用无需操作台二次确认；未勾选的连接保持只读。工具仍核验接收范围、账号、授权撤销与幂等编号。仅授权某个群不会额外允许私聊该群成员。已有连接不自动扩大权限。

「浏览聊天记录」中选择一条消息并点击「帮我拟回复」，只从该消息所在会话起草，正文可编辑。
生成草稿仍需配置并明确启用模型；草稿不会自动发送。

「发送与回复」可手工输入正文，或接收模型草稿。发送器目前只支持单行 1–2000 字文本。
在「配置接收目标」填写准确企微显示名、单聊/群聊类型和前台/后台方式，并勾选授权后保存。
保存只新增本地授权；真正发送必须先预览接收人和正文，再点击「确认发送这一条」。
回执未核对前保留本次编号，不自动重发；「关闭全部发送权限」可停止后续发送。

发送依赖独立的 `start-wecom-adapter.ps1` 服务（19091）；服务未启动时，操作台会显示连接失败，不能冒充已发送。
后台方式要求企微已打开且未最小化；也支持企微已在前台的情况。目标不在可见会话列表时，会尝试使用已识别的空白搜索框精确搜索；首次搜索定位可能触发企微自身的前台切换。已有其他搜索内容、重名或昵称无法准确匹配时会停止并说明原因。完整限制见 [适配器说明](WECOM_ADAPTER.md)。

## 当前边界

这是企微核心操作台，不宣称移植了原版全部模块。工作区、关注卡定时追踪、成长记忆、群管理与无人值守自动回复尚未接入。
服务运行时每秒检查已绑定企微账号的本地数据变化并自动同步；操作台显示同步状态和最近同步时间，支持暂停与恢复。新消息须先由企微同步至本机。
原始聊天浏览入口保持在 `/`，已有原文锚点链接继续有效。

## AI 意图识别与失败恢复（2026-10-09）

- 输入区默认勾选「AI 先理解意图」。点击「理解并继续」先向当前模型发送本次输入，返回发送、联系人搜索、记录查询或澄清意图。此请求不包含聊天记录，也不给模型执行工具。关闭后保留本地规则解析。
- 「我想给示例用户发条信息 hi」会提取接收人 示例用户、正文 hi。模型提出的姓名和正文须出现在用户输入中；异常响应或接口失败停止处理并显示错误。
- 发送仍须选择具体接收人、核对完整正文与发送方式，再确认发送。选择、修改、取消、发送确认不重复调用模型。记录分析仍由原有「本次允许调用模型」开关控制；只找联系人不会发送。
- 后台模式只定位当前会话或左侧可见目标，不再尝试无法截图核对的 Qt 搜索弹窗。需要搜索时选择前台桌面模式。
- 确定 NOT_SENT 的回执提供「改用前台，重新确认」；点击仅生成新预览，须再确认才会执行。UNKNOWN 回执不提供重试，保留先核对机制。
- 本次真实模型已验证上述输入，37 项初轮回归通过。Windows 截图工具本轮超时，真实发送送达尚未重新验证。


## 安装版 0.3.1

- 最近对话提供归档、恢复和删除。归档后只读，恢复后可继续；删除只清除操作台提问、回答和发送对话缓存，保留企微原始记录及发送幂等操作凭据。正在分析或发送的对话须等任务结束后管理。
- 移除重复的侧栏“发送与回复”入口。可以直接在输入框准备发送，或打开“发送设置”手动预览。
- 模型设置支持添加、编辑和删除（最多30项）。自定义模型分别保存加密密钥；更换 API 地址或接口类型后须重新填写密钥。已有导入组保留共用密钥规则。删除最后一个模型后保持未配置状态，不会重新启用旧环境变量中的模型。
- 双击安装版自动创建数据库，启动独立适配器和同步服务。首次检测到唯一企微账号时自动绑定与导入，多个账号时要求选择；已绑定账号不自动改绑。企微稍后登录时每5秒重新检测。每次启动重新检查解锁状态；重复打开同一安装目录只唤起原窗口。
- 打包脚本 `desktop/build_wecom.py` 使用明确的源码与依赖文件清单，附带 Python、OCR 和固定 WebView2。安装器校验所有文件 SHA-256，支持升级保留 data 和卸载保留数据。私有聊天、模型密钥、发送授权与原生发送实验不进入安装包。


## 0.3.2：动态进程与覆盖升级

读取器每次需要解锁时重新枚举当前运行的 WXWork.exe；页面不再保存或要求选择 PID。多个进程逐一通过所选账号数据库的校验来匹配，客户端重启期间重新枚举新 PID。旧页面提交的过期 pid 参数也不会固定读取目标。有效解锁缓存可复用；缓存失效时自动同步和手动读取都会重新查找运行进程。账号范围仍保持原有绑定，防止跨账号混入资料。

安装器优先读取已有安装登记的位置，选择原目录时显示“覆盖升级”。升级前从托盘彻底退出旧版，无需卸载；数据库、模型、授权及 .env 保留。失败时恢复原程序文件与安装清单，未完成恢复的备份保留。应用图标、启动页、安装器和企微页面使用用户提供的图片。
# 0.3.3 账号目录发现修复

读取器通过正在运行的 `WXWork.exe` 已打开的数据库文件定位账号，支持迁移到其他磁盘的数据目录，同时保留默认文档目录发现。多个历史账号中只有一个正在使用时，首次初始化优先选择该账号；已有绑定不自动改绑。

读取页面新增“账号未识别？指定企业微信数据目录”，接受 WXWork 根目录、账号目录或 Data 目录。只有包含 message.db、session.db、user.db 的目录才会保存；下次启动继续使用。找不到账号时显示目录提示并禁用无效解锁操作。

## 0.3.7

修复单聊会话名称为空时显示 S:账号_账号 的问题：按单聊双方稳定账号关联本机联系人名称，保留已有会话名或备注。同步时自动修复已导入历史的会话显示名称，不重新导入正文、不改变消息编号、接收账号和权限。联系人资料未缓存时保留已有名称或编号，不按昵称猜测。名称单独变化也会通知界面刷新；资料不变时通过持久化指纹跳过历史重写。

原生发送复用独立辅助进程、已验证的进程文件校验结果和已初始化的数据访问组件。文件路径、大小、时间、文件标识或进程创建时间变化会使校验缓存失效；每次仍核对授权、账号、接收人和原生函数。提交前只读取联系人/会话数据库，使用受支持版本会话表的 last_message_id；缺少该字段时保留完整消息库核对。等待回执期间跳过短时间内未变化的消息库重复解密，最多三秒重新核对一次。辅助进程超时会终止且不自动重试。
